

# WEEK 12 - FUNCTIONAL PROGRAMMING

## Summary

Functional Programming (FP) is a style of writing code that treats your programs like a series of mathematical functions, avoiding changing states or mutable data. Instead of writing step-by-step imperative instructions that tell the computer exactly how to do something, FP uses a declarative style, meaning you simply describe what you want to happen. Two of its most important rules are using "pure functions" and "immutable data". A pure function will always give you the exact same output every single time you give it the same input, and it will never cause unpredictable side effects by modifying things outside of its own scope. Immutability means that once you create a piece of data; like an array or an object, you never actually change it; instead, you create a brand-new copy containing the updates.

For a front-end developer, FP principles will be seen most often when working with lists of data using three incredibly powerful tools: map, filter, and reduce. The map() method takes an array, applies a function to every single item, and returns a brand-new array of the exact same length. The filter() method tests every item against a condition and returns a new collection containing only the items that passed the test. Finally, reduce() combines all the items in an array and collapses them down into a single value, like a total sum. The real magic happens when you chain these methods together into a single pipeline, allowing you to filter out bad data, transform what is left, and calculate a final result cleanly without ever needing to create messy intermediate variables.

Understanding these concepts is absolutely essential for modern web development, as popular JavaScript frameworks are built directly on FP principles. For example, in React, UI components are often written as pure functions where passing in the same properties always results in the same visual output. In state management libraries like Redux, "reducer" functions are strictly required to be pure and immutable, meaning they must return a new array rather than modifying the old state. Ultimately, adopting this functional style replaces verbose traditional loops with elegant code that is much easier to read, test, and debug, because any bugs are isolated to small, predictable functions rather than being hidden in a tangle of changing variables.
